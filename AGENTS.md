# AGENTS.md

## Project Overview

This repository contains a housing price predictor web application.

The project uses:
- Python for data processing and regression modeling
- pandas for data manipulation
- scikit-learn for regression
- Flask for the backend API
- HTML, CSS, and JavaScript for the frontend
- GitHub for version control and frontend hosting

## Project Structure

- `backend/train_model.py`
  - Loads and cleans the housing dataset
  - Trains the regression model
  - Evaluates model performance
  - Saves the trained model as `model.pkl`

- `backend/app.py`
  - Runs the Flask API
  - Loads the trained model
  - Accepts housing features from the frontend
  - Returns predicted housing prices

- `frontend/index.html`
  - Main user interface

- `frontend/style.css`
  - Website styling

- `frontend/script.js`
  - Handles user input and communicates with the backend API

- `data/housingB.csv`
  - Static housing dataset used to train the model

## Development Guidelines

- Keep data cleaning and model training inside `train_model.py`.
- Keep API logic inside `app.py`.
- Keep frontend code separate from backend code.
- Do not manually create or edit `model.pkl`.
- `model.pkl` should only be generated by `train_model.py`.
- Use clear variable names related to housing data.
- Add comments where regression or preprocessing logic may not be obvious.
- Avoid unnecessary frameworks or dependencies.
- Prefer simple, readable solutions suitable for a university analytics project.

## Modeling Guidelines

- Derive predictors from every CSV column except the configured target and control column, in CSV order.
- Use backend/model_settings.py for shared dataset parsing and predictor/type discovery.
- Do not maintain numeric_features/categorical_features lists in model_config.json; these are derived at runtime.
- feature_types provides optional type overrides, never a predictor inclusion list.
- Generate frontend metadata for new columns automatically; feature_schema.json contains optional display overrides.
- After dataset changes, retrain and restart Flask. Never reuse an artifact with different resolved settings.

- The target variable is housing price.
- Clearly separate predictors from the target.
- Handle missing values before model training.
- Encode categorical variables appropriately.
- Evaluate the model using metrics such as R², RMSE, and MAE.
- Avoid data leakage.
- Use the exact same preprocessing during prediction that was used during training.

## Frontend Guidelines

- Keep the interface simple and professional.
- Users should enter housing characteristics through a form.
- The frontend should send inputs to the Flask `/predict` endpoint.
- Display the predicted housing price clearly.
- Validate user inputs before sending them to the API.

## Important

Do not significantly change the repository architecture unless requested.

When making changes, preserve compatibility between:
1. Dataset preprocessing
2. Model training
3. API input format
4. Frontend input fields
